# Android 自动记账应用设计规格

日期：2026-07-22  
状态：待用户书面审核

## 1. 产品目标

开发一款以个人使用为首要目标、后续可发布的 Android 本地记账应用。应用通过读取支付宝、微信和银行的支付通知自动生成账目，同时支持完整的手动新增与编辑能力。用户可以查看日、周、月、年及自选日期范围的收入、支出和分类占比。

首版不要求登录或云同步。账本、解析规则和偏好均只保存在设备本地。

## 2. 技术路线

- 原生 Android：Kotlin 与 Jetpack Compose。
- 架构：分层架构，UI、业务规则、通知解析和数据存储相互独立。
- 本地数据：Room，底层使用 SQLite。
- 通知采集：Android `NotificationListenerService`。
- 设置存储：DataStore，用于保存主题、自动记账开关和其他轻量偏好。
- 后台处理：协程；需要延迟或可恢复任务时使用 WorkManager。

选择原生 Android 是因为通知权限、系统服务和后台限制的适配最直接，也便于后续正式发布。

## 3. 首版功能范围

### 3.1 自动记账

1. 首次开启时说明用途并引导用户授予通知使用权。
2. 只处理用户启用的支付来源，首版覆盖支付宝、微信及常见银行通知。
3. 在本机提取金额、时间、商户、来源账户和收支方向。
4. 高可信结果直接入账并发出简短确认通知；低可信结果进入“待确认”。
5. 根据商户和用户历史修改建立本地分类规则。
6. 使用来源、金额、时间窗口和脱敏摘要生成去重标识，避免重复入账。
7. 原始通知正文不长期保存；仅保存排查解析所需的脱敏摘要。

通知被隐藏、关闭或未包含金额时，应用不能保证自动记账。支付平台改变通知格式时，需要更新对应解析器。

### 3.2 手动记账与编辑

用户可以新增、修改和删除账目。编辑字段包括：

- 收支方向：收入或支出；
- 金额和币种；
- 日期与精确时间；
- 主分类和子分类；
- 商户、备注和账户；
- 是否为自己账户之间的内部转账；
- 是否待确认。

自动生成的记录使用同一个编辑页面，不限制用户修改。

### 3.3 分类与转账规则

分类和收支方向相互独立，同一分类可同时出现在收入和支出中。例如：

- 收到红包为收入，发出红包为支出，分类均为“红包”；
- 收到礼金为收入，赠送礼金为支出，分类均为“礼金”；
- 收到他人转账为收入，转给他人为支出，分类均可为“转账”。

自己名下账户之间的内部转账保留记录，但不计入收入、支出、结余、饼图或分类排行。自动识别无法判断是否为内部转账时，记录进入“待确认”。

内置支出分类包括餐饮、交通、日用、购物、零食、饮品、蔬菜、水果、服饰、娱乐、美容、通讯、医疗、学习、游戏、住房、礼品、宠物、汽车、数码、办公、运动、捐赠、彩票、红包、礼金、转账和其他。

内置收入分类包括红包、工资、奖金、理财、分红、礼金、退款、转账和其他。用户可添加、排序、重命名或隐藏分类。

### 3.4 统计

- 日统计：本地时间 00:00 至 23:59。
- 周统计：周一至周日。
- 月统计：自然月。
- 年统计：自然年。
- 自选统计：用户可自由选择单日或任意起止日期。
- 收入与支出可独立切换查看饼图、总额和分类排行。
- 点击饼图分类可查看构成该分类的账目。
- 新增、修改或删除记录后，所有统计即时重新计算。
- 内部转账不参与统计；他人转账按实际方向参与统计。

金额计算始终使用整数最小货币单位，避免浮点误差。

## 4. 页面与交互

底部导航固定为五个入口，中央新增按钮与导航栏齐平，不使用突出的黄色圆形按钮。

### 4.1 首页

- 今日收入、支出和结余；
- 自动记账状态；
- 最近账目；
- 待确认记录提示；
- 点击记录进入编辑页。

### 4.2 账单

- 按日期分组显示所有流水；
- 支持年月、收入/支出、账户和分类筛选；
- 支持搜索商户、备注和金额；
- 点击记录查看和编辑，删除操作需要二次确认。

### 4.3 记一笔

- 切换收入或支出；
- 输入金额并选择分类；
- 选择账户、时间、商户和备注；
- 标记内部转账；
- 保存后立即更新账单和统计。

### 4.4 统计

- 切换日、周、月、年和自选日期；
- 切换收入或支出；
- 展示总额、分类饼图和分类排行；
- 从分类下钻查看对应账目。

### 4.5 设置

- 自动记账开关、通知权限状态和来源开关；
- 外观主题切换；
- 分类和账户管理；
- 本地备份与恢复；
- 应用锁、隐私说明和清空账本。

## 5. 视觉系统

首版保留三套可切换主题，功能和数据结构完全一致：

1. 清新薄荷：高留白、白色卡片和薄荷绿主色；
2. 小票账本：以票据卡片承载当天流水；
3. 纸感极简：低饱和米白与深绿色，呈现纸质账簿质感。

主题偏好保存在本地，切换时不重启应用、不影响当前页面和数据。默认使用清新薄荷。

统一字号建议：页面标题约 20sp，正文 14sp，辅助文字 11–12sp，主要金额 26–28sp。系统字体缩放后界面仍须可读，不裁切重要内容。

## 6. 数据模型

核心实体包括：

- `Transaction`：账目方向、金额、币种、时间、商户、备注、账户、分类、来源、待确认状态、内部转账标记、退款关联、脱敏摘要、去重标识及创建/修改时间；
- `Category`：名称、图标、颜色、排序、显示状态和适用方向；
- `Account`：账户名称、类型、显示状态和排序；
- `MerchantRule`：商户匹配规则、目标分类和用户修正次数；
- `ParserRuleVersion`：通知来源与解析规则版本，便于兼容格式变化。

所有金额使用 `Long` 保存最小货币单位。数据库修改通过事务完成，避免账目与关联数据处于不一致状态。

## 7. 数据流与模块边界

1. 通知采集模块只负责接收允许来源的通知并交给解析器。
2. 来源解析器生成统一的候选账目，不直接写数据库。
3. 业务规则模块执行去重、方向判断、商户分类和可信度判断。
4. 账本仓库负责验证并持久化记录。
5. 统计模块只读取统一账本数据，按日期、方向和内部转账规则聚合。
6. Compose 页面通过 ViewModel 获取状态并提交用户操作。

每个支付来源使用独立解析器，某一来源格式变化不会影响其他来源。

## 8. 异常与隐私处理

- 通知权限关闭：首页显示一次持续状态提示，不频繁弹窗。
- 无金额或格式未知：不直接计入正式账本，进入待处理列表。
- 重复通知：命中去重标识时忽略，并保留可诊断事件计数。
- 退款：优先关联原交易；无法关联时建立独立收入并标记“退款”。
- 备份损坏或版本不兼容：恢复前验证，不覆盖当前数据库，并给出可理解的错误信息。
- 清空账本：展示记录数量和不可撤销提示，二次确认后执行。
- 隐私：不联网上传通知、账本、商户规则或统计数据；不申请与首版无关的权限。

## 9. 备份与恢复

首版提供用户主动触发的本地导出与恢复。备份包含账目、分类、账户、商户规则和主题偏好。恢复前自动创建当前数据的安全副本，验证成功后再替换。

备份文件应包含格式版本，以便后续应用升级时迁移。首版不包含自动云备份。

## 10. 验收与测试

- 手动新增、编辑、删除、搜索和筛选均正确；
- 支付宝、微信和选定银行的样例通知能正确解析；
- 重复通知不会生成重复账目；
- 收入、支出、红包、礼金、退款、他人转账和内部转账统计符合规则；
- 日/周/月/年及自选日期在跨月、跨年和时区边界下正确；
- 修改记录后饼图、排行和总额立即更新；
- 三套主题可即时切换且数据状态保持不变；
- 常见 Android 屏幕和系统字体缩放下没有遮挡或关键文字裁切；
- 权限关闭、解析失败、备份损坏和低存储空间时不会导致账本损坏；
- 应用重启后账目、分类规则、账户和主题仍正确保留。

## 11. 首版不包含

- 用户账号、云同步和多人共享账本；
- iOS、网页或 Windows 客户端；
- 自动读取短信、支付应用内部数据库或银行接口；
- 预算、债务、投资收益分析和发票 OCR；
- 广告、订阅和付费功能。

这些能力可在首版稳定后单独评估，避免扩大通知权限和数据模型的初始风险。

## 12. 所需开发软件

设计审核通过后安装以下工具：

- Android Studio 稳定版，包含 Android SDK、SDK Platform Tools 和模拟器；
- Git for Windows；
- Android Studio 自带的 JetBrains Runtime/JDK，不额外安装独立 Java；
- 一个匹配目标 Android API 的模拟器系统镜像。

Gradle、Kotlin、Compose、Room 和测试依赖由项目构建系统管理，无需单独安装桌面软件。真机调试时需要启用 Android 开发者选项和 USB 调试。
