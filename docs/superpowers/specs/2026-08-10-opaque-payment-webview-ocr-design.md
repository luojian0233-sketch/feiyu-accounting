# 微信与支付宝空文本 WebView OCR 兜底设计

日期：2026-08-10

## 背景与根因

实机 PKG110（Android API 36）上的微信支付详情运行在 `com.tencent.mm/.plugin.webview.ui.tools.MMWebViewUI`。该页面在无障碍树中属于微信包，但文本节点数量为 0。现有自动页面识别控制器只在页面解析结果为 `INCOMPLETE_FIELDS` 时调用截图 OCR；空文本树被解析为 `NOT_PAYMENT_PAGE`，因此 OCR 从未启动，刚完成的 ¥1.00 微信支出没有进入识别流程。

通知读取不能覆盖这个场景：微信位于前台时，本次支付没有留下可读取的系统支付通知。因此需要一个受限的页面 OCR 兜底，而不是放宽通知解析或持久化原始页面内容。

## 目标

- 微信或支付宝已授权且来源已开启时，空文本页面可以尝试一次内存截图 OCR。
- 只有 OCR 结果满足现有支付页解析器的签名、金额和方向约束时，才产生规范化候选交易。
- 普通聊天页面和可读的普通网页不触发新增兜底。
- 截图、无障碍原文和 OCR 原文始终不落盘、不写日志、不进入通知内容。
- 重复窗口事件不会造成高频截图、重复 OCR 或重复入账。

## 非目标

- 不根据 `MMWebViewUI` Activity 名称直接认定支付页面。
- 不保存截图用于历史重放。
- 不放宽微信或支付宝之外的包过滤。
- 不绕过自动记账总开关、来源开关、系统无障碍授权、现有去重或待确认规则。
- 不在本次修改中增加云端识别、网络权限或后台上传。

## 方案比较

### 方案 A：受限空文本树 OCR（采用）

仅对已允许的微信/支付宝包，在设置允许且 `PageSnapshot.elements` 为空时调用现有截图网关和本地 OCR。OCR 结果仍交给现有平台解析器判定。

优点：覆盖实机 WebView；仍由支付签名与金额规则决定是否入账；不依赖微信内部 Activity 名称。缺点：空白的普通 WebView 也可能触发一次内存 OCR，因此必须节流并严格丢弃非支付结果。

### 方案 B：只使用快捷设置截图记账

安全边界最窄，但每次需要用户手动触发，不满足自动记账目标。

### 方案 C：按内部 Activity 名称放行

开销较小，但 `MMWebViewUI` 同时承载普通网页，而且内部类名可能随微信版本变化，可靠性和可维护性不足。

## 数据流与组件变更

1. `PaymentPageAccessibilityService` 继续只接收微信和支付宝的窗口状态/内容变化，并生成脱敏 `PageSnapshot`。
2. `AutoPageRecognitionController` 先执行现有总开关、来源开关和包过滤。
3. 可读页面继续沿用现有解析路径；`NOT_PAYMENT_PAGE` 不截图。
4. 仅当页面文本元素完全为空时，控制器申请一个空页面 OCR 节流保留项，再调用现有 `AccessibilityCaptureGateway.capture()`。
5. 截图交给本地 ML Kit OCR，形成仅存在于内存中的 `PageSnapshot`。
6. OCR 快照由原微信或支付宝解析器处理：
   - `Single`：交给现有 `RecognitionCoordinator`；
   - `Multiple`：沿用现有多候选流程；
   - `Rejected`：不保存任何交易或原始数据。
7. Bitmap 所有权继续由控制器在 `finally` 中回收；捕获失败、OCR 失败、取消和拒绝均不泄漏图片。

## 节流与去重

- 可读页面继续使用现有 `RecognitionDebouncer`。
- 空文本页面使用独立、容量有界的节流器，键为平台包名与当前空页面摘要；空树时摘要退化为平台包名。
- 同一空页面在 2 秒冷却窗口内只允许一次截图 OCR；捕获或 OCR 的瞬时失败在 2 秒后可重试，不形成永久封锁。
- 一旦解析出候选，仍由现有证据摘要和 Room 唯一约束完成跨通知、页面与截图去重。
- 节流表必须按时间淘汰，硬容量为 64 项，避免无障碍服务长时间运行后增长无界。

## 隐私与安全边界

- 只允许 `com.tencent.mm` 和 `com.eg.android.AlipayGphone`。
- 必须同时满足自动记账总开关、对应来源开关和系统无障碍服务已启用。
- 截图和 OCR 原文仅存在于内存；不写文件、数据库、偏好、日志或通知。
- 数据库只接收现有规范字段：平台、事件类型、方向、金额、可选商户/账户、时间、置信度和摘要。
- OCR 未看到支付签名或金额时 fail closed，不生成待确认占位记录。
- 取消异常继续传播；其他捕获/OCR异常只更新脱敏诊断枚举。

## 错误处理

- 无障碍权限丢失：记录 `PERMISSION_MISSING`，不降级为未经授权的投屏捕获。
- 截图失败或前后台包变化：记录 `CAPTURE_FAILED`，回收已取得的 Bitmap，不保存。
- OCR 异常：记录 `OCR_FAILED`，回收 Bitmap，不保存。
- OCR 解析为非支付页或字段不足：不保存；冷却期后允许用户重新打开详情页再次触发。
- 处理期间设置关闭或协程取消：立即停止，取消不得转换为普通失败。

## 测试设计

测试必须先失败再实现，覆盖：

1. 微信空文本快照触发一次截图 OCR，并可保存 OCR 识别出的支付候选。
2. 支付宝空文本快照走对应解析器。
3. 普通、非空且无支付签名的聊天/网页不调用截图。
4. 总开关、来源开关或平台包不允许时，空页面也不截图。
5. 空页面截图 OCR 后仍为非支付内容时，零持久化。
6. 捕获失败、OCR 异常、取消与前后台包变化时，零持久化且 Bitmap 恰好回收。
7. 同一空页面事件突发只截图一次；冷却到期后可重试；节流表容量有界。
8. 同一交易同时由通知和空页面 OCR 命中时仍只保存一次。
9. 隐私契约继续验证无截图/OCR 原文落盘，Manifest 不新增网络、存储或悬浮窗权限。

## 实机验收

1. 使用 `adb install -r` 覆盖安装，安装前后读取交易数量，确认恢复后的 1 笔基线不变。
2. 不再运行会卸载个人安装实例的 `connectedDebugAndroidTest`。
3. 保持自动记账、微信来源、通知读取和无障碍页面识别开启。
4. 重新打开已经完成的 ¥1.00 微信支付详情，不再次付款。
5. 确认只产生一条 ¥1.00 支出或一条待确认记录；确认后账本从 1 笔变为 2 笔，统计只增加一次。
6. 再次打开同一详情页，确认不会重复入账。

## 成功标准

- 回归测试和现有 JVM 测试通过，AndroidTest 源码可编译，Debug APK 可构建。
- 覆盖安装保留恢复后的账本基线。
- 同一微信支付详情无需再次付款即可被识别，并且重复打开不会产生第二条记录。
- 未新增原始截图/OCR持久化、网络权限或跨包识别范围。
