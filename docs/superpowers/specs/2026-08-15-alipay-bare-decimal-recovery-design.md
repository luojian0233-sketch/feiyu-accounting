# 支付宝详情页唯一裸金额恢复设计

## 背景与证据

现有真机诊断已确认同一支付宝账单详情页满足以下条件：

- 自动记账与支付宝来源开关已开启；
- 无障碍原始快照包含精确的 `账单详情` 锚点；
- 无障碍截图与本地 OCR 成功；
- OCR 结果不含人民币货币符号，但恰好包含一个格式为整数加两位小数的独立文本元素；
- 可信详情锚点合并后，支付宝解析结果从 `NOT_PAYMENT_PAGE` 前进为 `INCOMPLETE_FIELDS`，缺失字段被进一步定位为金额。

诊断过程仅输出固定枚举和计数，没有输出、记录或持久化金额、商户、账户、页面原文或截图。临时诊断代码已经删除，设备已恢复为无诊断日志的 APK。

## 目标

当支付宝账单详情页的 OCR 唯一遗漏人民币符号时，在内存中把唯一、严格的裸两位小数恢复为人民币金额，使现有 `AlipayPageParser` 能继续完成方向、时间、金额歧义和页面语义验证。

## 非目标

- 不全局允许裸数字作为金额；
- 不修改微信、通知解析、手动截图或系统录屏识别规则；
- 不从无障碍快照复制金额、方向、商户、账户、时间或事件语义；
- 不加入二次截图、图片裁剪、云端 OCR 或网络权限；
- 不放宽多个金额、整数金额、三位及以上小数或带其他文本的数字。

## 方案选择

采用独立的受限金额恢复器，而不是修改通用金额解析器或增加二次 OCR：

1. **受限预处理（采用）**：只在支付宝官方包、精确详情锚点、无现成货币金额、唯一裸两位小数同时成立时，为该 OCR 元素补充人民币语义。范围最小，且可以独立测试。
2. **通用解析器接受裸金额（拒绝）**：会影响其他平台和截图入口，误把日期、余额或订单字段当金额的风险更高。
3. **局部裁剪后二次 OCR（暂不采用）**：可能提升复杂页面识别率，但增加图像区域选择、生命周期和设备适配复杂度，当前证据不需要这一层。

## 架构

新增纯 Kotlin 组件 `TrustedAlipayBareAmountRecovery`。它接收原始无障碍 `PageSnapshot` 与 OCR 元素列表，返回新的 OCR 元素列表；不访问数据库、Android 服务、日志或文件。

`AutoPageRecognitionController.processCapturedBitmap` 的顺序为：

1. 本地 OCR 产生元素；
2. `TrustedAlipayBareAmountRecovery` 尝试恢复唯一裸金额；
3. `TrustedAccessibilityAnchorMerger` 合并精确详情锚点；
4. 构造新的 OCR `PageSnapshot`；
5. 交给现有 `AlipayPageParser`；
6. 只有现有解析器产出候选后才进入协调器、去重与持久化。

## 恢复条件

恢复器必须同时满足全部条件，否则原样返回 OCR 元素：

1. 原始快照包名精确等于 `com.eg.android.AlipayGphone`；
2. 原始无障碍元素中至少有一个文本在 `trim()` 后精确等于 `账单详情` 或 `账单明细`；
3. OCR 元素中不存在可识别的人民币金额文本，货币前缀包括 `¥`、`￥`、`人民币`、`CNY`、`RMB`；
4. OCR 元素中恰好有一个元素，其 `trim()` 后完整匹配 `[0-9]{1,8}[.,][0-9]{2}`；
5. 裸金额不允许正负号、空格、标签、单位或任何其他字符。

满足条件时只复制该 OCR 元素，并把复制后的文本规范化为 `¥` 加原两位小数字符串；保留原边界坐标。原列表、原快照和位图均不修改。逗号小数分隔符在恢复时规范化为句点。

## 失败关闭

以下情况均不恢复：

- 包名错误或为空；
- 没有精确详情锚点，仅出现 `支付宝`、包含式文本或普通页面标题；
- 已存在任何人民币货币金额；
- 裸两位小数为零个或多个；
- 数字为整数、超过八位整数、不是恰好两位小数、带符号或混入其他字符。

不恢复时继续沿用现有解析结果，不自动保存，也不弹出错误详情。

## 测试设计

纯组件测试先红后绿，至少覆盖：

- 精确支付宝详情锚点加唯一 `1.00` 被恢复；
- `账单明细` 同样受支持；
- 错误包名、无锚点、宽松包含文本均不恢复；
- 已有货币金额时不恢复裸数字；
- 零个或多个裸候选不恢复；
- 整数、一位/三位小数、带符号、带标签、超长整数不恢复；
- 输入列表和元素边界不被修改。

控制器集成测试先证明“锚点 + OCR 唯一裸两位小数”当前不会产生候选，再接入恢复器，断言生成支付宝支出候选、金额换算正确并回收位图。现有微信、无障碍、截图控制器和支付页解析回归必须继续通过。

## 隐私与权限

- 所有恢复只发生在进程内存中；
- 不记录 OCR 文本、金额、页面原文或位图；
- 不新增 Receiver、Provider、文件、数据库字段或权限；
- 最终 APK 必须不含临时诊断标签和调试接收器；
- 继续保持无网络、无存储和无悬浮窗权限合同。

## 真机验收

1. 使用 `adb install -r` 覆盖安装，保留现有账本；
2. 核对通知监听与无障碍服务已连接；
3. 打开已有支付宝详情页，不进行新支付；
4. 等待自动识别，确认产生一条待确认记录，或若已有同 digest 记录则确认去重结果；
5. 若产生待确认记录，选择 `其他` 并保存；
6. 再次打开同一详情页，确认记录数量不增加；
7. 所有直接 ADB 命令保持 10 秒超时，不运行 connected 测试、不卸载、不清数据、不重启 ADB。
