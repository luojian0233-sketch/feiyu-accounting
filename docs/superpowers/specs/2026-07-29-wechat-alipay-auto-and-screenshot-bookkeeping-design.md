# 微信、支付宝自动识别与一键截屏记账设计

日期：2026-07-29  
状态：功能设计已获用户口头确认，待书面规格审阅

## 1. 背景

当前 Android MVP 已支持手动记账、通知读取、微信/支付宝/银行通知解析、账单编辑、商户分类规则、日周月年统计和收入/支出饼图。真机测试发现，微信真实支付通知通常只有“微信支付 / 已支付¥金额”，能够确认支出金额，却无法提供商户、支付方式和可靠分类。

此前的微信支付页识别设计只解决“通知后手动打开微信支付页补全记录”。本设计将其扩展为两种正式功能：

1. 微信和支付宝的支付、收款、退款、转账、红包页面出现后自动识别并记账。
2. 用户在任意支付结果或账单页面点击状态栏“截屏记账”快捷按钮，立即进行本地识别。

当前阶段以用户自用和识别成功率为第一优先级。权限数量、商店发布约束和极致省电不是首版阻塞项，但仍禁止绕过系统授权、上传页面内容或长期保存截图。

本规格取代 `2026-07-27-wechat-payment-page-recognition-design.md` 中尚未实施的页面识别范围；原有手动记账、主题、统计和通知功能继续保留。

## 2. 目标

1. 自动识别微信和支付宝的收入与支出。
2. 支持消费、收款、退款、转账和红包等主要交易类型。
3. 从通知、前台支付页面和用户主动截屏中提取金额、方向、交易类型、商户或交易对象、支付账户和可见时间。
4. 高可信且分类明确时自动入账；信息不完整、方向冲突、分类未知或候选不唯一时进入确认页。
5. 三条识别链路共享统一匹配与去重逻辑，同一笔交易最多生成一条账目。
6. 未知商户经用户确认一次分类后形成本地规则，后续自动分类。
7. 自动账目立即进入账单、日周月年统计以及收入/支出饼图。
8. 覆盖安装和数据库升级必须保留现有账本、分类、账户、商户规则和设置。

## 3. 非目标

- 不自动点击、滑动、输入、支付、退款或操控微信和支付宝。
- 不读取聊天记录、联系人列表、余额、完整订单号或与记账无关的页面。
- 不持续录屏，不在后台周期性截取任意应用。
- 不保存完整截图、无障碍节点原文或 OCR 原文。
- 不上传页面、通知或识别数据。
- 不以绕过 Android 系统授权为目标。
- 首版不加入悬浮球；状态栏快捷按钮为主动截屏的唯一入口。
- 首版不承诺所有银行 App 的自动页面识别；银行及其他应用可使用通知解析或主动截屏。

## 4. 方案选择

采用“通知识别 + 微信/支付宝前台页面识别 + 状态栏主动截屏 + 本地 OCR + 统一候选协调器”的混合方案。

未采用仅通知方案，因为真实通知经常缺少商户和分类。未采用持续录屏方案，因为它会增加耗电、误识别和隐私风险，却不会明显提升支付完成瞬间的实用性。未采用悬浮球，因为状态栏快捷按钮已能提供稳定、低干扰的主动入口。

## 5. 总体架构

### 5.1 捕获层

捕获层只负责获得一次交易线索，不直接写入账本：

- `PaymentNotificationService`：接收已启用来源的通知。
- `PaymentPageAccessibilityService`：只对微信和支付宝的前台窗口变化执行自动页面识别。
- `ScreenshotBookkeepingTileService`：提供状态栏“截屏记账”快捷按钮。
- `ScreenCaptureGateway`：优先使用无障碍截屏；不可用时通过可见授权页请求一次系统截屏授权。

自动页面识别限定包名：

- 微信：`com.tencent.mm`
- 支付宝：`com.eg.android.AlipayGphone`

主动截屏由用户明确点击触发，可处理当前屏幕上的其他应用，但不会因此启用对其他应用的持续监听。

### 5.2 提取层

每次捕获按以下顺序处理：

1. 优先读取结构化通知字段或无障碍节点文字与边界。
2. 页面节点不完整，或用户主动点击截屏记账时，调用随 APK 提供的中文本地 OCR。
3. 将不同来源统一为 `RecognitionCandidate`。
4. 立即释放位图、节点快照和完整文本。

`RecognitionCandidate` 至少包含：

- 平台：微信、支付宝、其他或未知；
- 捕获渠道：通知、自动页面、主动截屏；
- 交易类型：消费、收款、退款、转账、红包或未知；
- 收支方向；
- 金额与币种；
- 商户或交易对象；
- 支付账户；
- 页面可见时间或捕获时间；
- 字段级可信度；
- 仅由规范化交易特征生成的摘要，不含页面原文。

### 5.3 协调层

`RecognitionCoordinator` 是三条捕获链路的唯一入账入口，负责：

- 规范化金额、商户、账户、时间和事件类型；
- 查找已有待确认账目；
- 合并同一交易的多条线索；
- 应用商户规则和内置事件分类；
- 判断自动保存或进入确认页；
- 保存脱敏识别凭据，阻止同一页面或通知重复处理。

现有通知解析器不再直接创建最终账目，而是向协调器提交候选。

### 5.4 展示层

- 设置页新增“自动记账”页面。
- 复用现有手动记账编辑能力，增加可预填的“识别结果确认”入口。
- 成功自动入账时显示轻量通知，例如“已记入支出 ¥12.80 · 餐饮”。
- 需要确认时打开预填编辑页，用户可改金额、方向、类型、分类、账户、商户和时间。

## 6. 自动页面识别

### 6.1 触发条件

仅在下列条件同时满足时运行自动提取：

- 自动记账总开关已开启；
- 对应微信或支付宝来源开关已开启；
- 当前前台包名与来源一致；
- 页面存在支付结果、收款到账、退款、转账或红包的明确结构和关键词。

普通聊天、首页、营销页、余额页和历史账单列表不会自动创建账目。

### 6.2 微信

微信识别至少覆盖：

- “微信支付 / 已支付¥金额”通知；
- 支付成功或微信支付卡片；
- 收款到账；
- 退款到账；
- 转账收入与转账支出；
- 红包收入与红包支出。

支付页优先提取商户、金额、支付方式和时间。历史页面出现多个支付卡片时，只有最上方最新卡片与最近候选唯一匹配才允许自动补全；否则进入确认流程。

### 6.3 支付宝

支付宝识别至少覆盖：

- 支付成功；
- 收款到账；
- 退款成功或退款到账；
- 转账收入与转账支出；
- 红包收入与红包支出。

支付宝页面同样要求包名、页面签名和交易结构同时成立。仅出现余额、优惠券、总资产或营销金额时不得入账。

### 6.4 方向和事件规则

- 消费：支出。
- 收款：收入。
- 退款到账：收入，分类为“退款”；若能唯一匹配原支出则设置退款关联。
- 转账：依据“转入、收到、收款”或“转出、付款、已支付”等明确方向记录收入或支出。
- 红包：依据“收到红包”或“发出/支付红包”记录收入或支出，分类为“红包”。
- 只有用户明确标记为自己账户之间转移时，才设置 `internalTransfer=true`；平台内给他人的转账不是内部转账。
- 方向冲突或缺失时不得猜测。

## 7. 一键截屏记账

### 7.1 入口

提供 Android 快速设置磁贴，名称为“截屏记账”。首次进入设置页时显示“添加到状态栏”的引导和系统入口。

典型流程：

1. 用户停留在任意支付结果、订单详情或账单页面。
2. 下拉快速设置并点击“截屏记账”。
3. 磁贴收起，应用截取当前屏幕并在本机 OCR。
4. 高可信结果直接入账；不确定结果打开确认页。
5. 显示成功、需要确认或识别失败的简短反馈。

### 7.2 截屏方式

- API 30 及以上优先调用已启用无障碍服务的截屏能力；当前主验收设备 API 36 走完整流程。
- 无障碍截屏不可用时，启动可见授权页请求系统截屏授权，并只处理当前一次操作。
- API 26–29 若无法从无障碍服务截屏，使用系统截屏授权回退。
- 页面使用安全窗口导致黑屏或系统拒绝捕获时，明确提示失败，不创建账目。

### 7.3 识别约束

- 必须检测到交易语义和唯一主金额，不能仅凭屏幕上出现“¥1.00”入账。
- 同时出现多个账单卡片、多个主金额或多个交易方向时进入候选选择页。
- 对微信、支付宝外的应用，平台可记为“其他”，但金额、方向和交易类型仍必须达到保存条件。

## 8. 自动保存与确认

只有以下字段全部明确时才自动保存：

- 唯一主金额；
- 唯一收支方向；
- 明确交易类型；
- 已知分类；
- 商户、交易对象或事件类型足以形成稳定规则；
- 不存在重复候选或方向冲突。

分类来源按优先级排序：

1. 用户保存的精确商户规则；
2. 内置高确定性商户规则；
3. 明确事件分类，例如退款、转账和红包；
4. 用户确认。

内置规则首批包括中国电信、中国移动和中国联通映射到“通讯”。用户在确认页修改分类并保存后，为规范化商户生成本地规则。用户规则优先于内置规则。

任何字段不满足自动保存条件时，创建或更新一条不计入统计的待确认记录，并打开预填确认页。用户确认后才进入统计。

## 9. 匹配与去重

### 9.1 识别凭据

新增脱敏识别凭据，保存：

- 关联交易 ID；
- 捕获渠道；
- 平台；
- 事件类型；
- 观察时间；
- 规范化交易特征的 SHA-256 摘要。

摘要不包含可还原的通知正文、页面原文、完整订单号或截图。相同摘要只能处理一次。

### 9.2 匹配顺序

协调器按以下顺序处理候选：

1. 摘要已存在：忽略。
2. 存在同平台、同方向、同金额、15 分钟内的唯一待确认账目：补全该账目。
3. 存在同平台、同方向、同金额、同事件类型且 2 分钟内唯一的已确认账目：附加识别凭据但不新建账目；双方都有商户时还必须商户一致。该规则覆盖“页面先识别、通知后到达”和“通知先到达、页面后识别”两种顺序。
4. 候选不唯一：保持待确认并让用户选择。
5. 无候选且满足自动保存条件：创建已确认账目。
6. 无候选但信息不足：创建待确认账目。

仅金额相同不能证明是同一交易。连续两笔同金额交易如果缺少可区分的商户、时间或事件特征，必须交由用户选择，不得自动合并。

## 10. 数据模型变化

在不删除现有列和数据的前提下进行 Room 数据库迁移：

- `transactions` 增加 `platform`、`eventKind` 和 `recognitionConfidence`：现有账目迁移时分别使用 `UNKNOWN`、`UNKNOWN` 和 `100`，保证手动账目无需重新确认。
- `Source` 扩展为通知、自动页面和主动截屏来源；多渠道证据由识别凭据表记录。
- 新增 `recognition_receipts` 表，字段为交易 ID、捕获渠道、平台、事件类型、观察时间和脱敏摘要；摘要建立唯一索引，交易删除时凭据随之删除。
- 复用现有 `merchant_rules`、`categories` 和 `accounts`。
- 保留现有 `dedupeKey`，用于兼容已入库通知记录；新协调器同时使用识别凭据完成跨渠道去重。

数据库迁移必须具备自动化测试，覆盖现有版本 2 数据升级及原有账目完整性。

## 11. 权限与运行策略

设置页提供一次性权限向导，按顺序引导：

1. 通知读取权限；
2. 微信和支付宝来源开关；
3. 页面识别服务；
4. 通知展示权限；
5. 必要时的系统截屏授权；
6. 当前设备可用的后台运行或电池优化设置入口。

为了首版实用性：

- 页面识别失败时立即尝试本地 OCR。
- 服务被系统停止或权限被撤销时，在下次打开应用时直接显示恢复入口。
- 不为了减少权限而禁用已获用户授权的有效识别链路。
- 状态栏快捷截屏不依赖悬浮窗权限。

Android 要求用户在系统界面主动授予通知读取、无障碍或截屏授权；应用只负责解释用途并打开正确入口，不尝试绕过。

## 12. 设置页面

路径：“我的 → 自动记账”。页面沿用当前简洁排版和用户选择的三套主题。

### 12.1 自动记账卡片

- 自动记账总开关；
- 通知读取状态与设置入口；
- 微信自动识别开关；
- 支付宝自动识别开关；
- 页面识别服务状态与设置入口；
- 支持交易说明：消费、收款、退款、转账、红包；
- 最近一次脱敏诊断，例如“识别成功”“字段不完整”“发现多个候选”“服务未开启”。

### 12.2 一键截屏记账卡片

- 添加“截屏记账”快捷按钮的引导；
- 本地 OCR 状态；
- “高可信结果自动入账”开关，默认开启；
- “不确定时让我确认”固定开启；
- 最近一次主动截屏结果。

不加入会员试用、广告、视频教程和参考图中的商业化内容。

## 13. 状态反馈和错误处理

- 自动保存成功：显示金额、方向和分类，不显示完整页面内容。
- 需要确认：打开预填编辑页。
- 未发现交易结构：提示“未识别到完整账单”，不创建记录。
- 多个金额或多个卡片：进入候选选择页。
- OCR 失败：记录脱敏错误类型，不保存位图或原文。
- 截屏被安全窗口阻止：提示该页面无法截取。
- 权限关闭：停止对应链路，保留其他记账功能和已有数据。
- 数据库更新失败：原交易保持不变，反馈可重试状态。
- 服务或进程重启：已存在的识别摘要继续阻止重复入账。

## 14. 隐私与数据边界

实用性优先不改变以下底线：

- 位图、无障碍节点快照和完整 OCR 文本只存在于内存，识别结束立即释放。
- 数据库、文件、日志、备份和诊断信息不得包含截图或页面原文。
- 不申请广泛文件存储权限，不申请网络权限用于识别。
- 只持久化记账所需字段和不可逆摘要。
- 自动页面监听只订阅微信和支付宝；其他应用只有用户主动点击截屏时处理一次。

## 15. 测试设计

严格按测试驱动开发实施。

### 15.1 JVM 单元测试

- 微信“微信支付 / 已支付¥1.00”生成支出候选。
- 微信和支付宝的消费、收款、退款、转账、红包正反向样本。
- 优惠、余额、总资产、聊天、多个金额和方向冲突样本被拒绝或要求确认。
- 节点文字与 OCR 结构统一转换为 `RecognitionCandidate`。
- 商户、账户、金额、时间和事件类型规范化。
- 用户商户规则优先于内置规则。
- 中国电信、中国移动和中国联通归类为“通讯”。
- 退款、转账和红包应用正确事件分类。
- 三渠道同一交易合并为一笔。
- 连续两笔同金额交易不被错误合并。
- 重复识别摘要被忽略。
- 自动保存阈值和待确认规则。
- 数据库版本 2 升级后现有数据完整。

### 15.2 Android 仪器与组件测试

- 设置页显示开关、权限状态、恢复入口和两张功能卡片。
- 微信和支付宝之外的无障碍窗口事件不会触发自动页面识别。
- 快速设置磁贴触发一次截屏请求。
- API 30+ 截屏与 OCR 流程不写入图片文件。
- 截屏授权取消、安全窗口、OCR 失败和多个候选均有正确反馈。
- 识别确认页可修改并保存全部字段。
- 自动账目正确进入账单、统计和饼图。
- 三套主题下新增页面均可读、可操作且字体不过度突出。

### 15.3 真机验收

主设备：PKG110，Android 16 / API 36。

1. 所有 ADB 命令设置 10 秒超时，不重启 ADB，不要求拔插设备。
2. 覆盖安装 APK，不清除应用数据。
3. 确认现有手动账目、分类、账户和设置均保留。
4. 完成一次微信消费和一次支付宝消费，验证金额、商户、账户及分类。
5. 完成或使用可控样本验证两平台的收款、退款、转账和红包方向。
6. 验证通知先产生候选、页面识别后补全，最终只有一笔记录。
